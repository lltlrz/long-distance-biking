# RidePilot 骑迹计划

RidePilot 是一个面向多日长途骑行的 AI 辅助规划项目，帮助骑行者制定每日行程、选择停留点、了解补给空窗与道路风险，并在体力、天气或时间发生变化时生成调整建议。

项目包含产品方案、PRD、用户流程、信息架构、原型文档，以及基于原生网页和 Python 的可交互应用，覆盖从产品设计到 Agent 工具调用的完整实践。

## 核心功能

- **骑行规划**：通过表单或自然语言输入起终点、天数、强度和偏好，生成每日行程。
- **补给分析**：查询示例餐饮、便利店、超市、住宿、城镇、医疗及维修点，计算沿途补给间隔。
- **终点推荐**：按住宿可达性40%、补给服务25%、里程匹配20%、安全性15%计算候选停留点评分。
- **风险提醒**：展示道路、隧道桥梁、爬升、弱网络及补给风险，并结合用户报告的天气和剩余时间提供建议。
- **途中调整**：根据当前日期、当天已骑距离、疲劳、天气和剩余可骑时间重算后续行程，确认后才应用建议。
- **对话与执行记录**：支持携带历史消息和当前行程的对话，展示后端工具调用的参数、结果和状态。
- **行程展示与保存**：提供地图示意、每日卡片、补给图层筛选，并支持将当前行程保存到浏览器。

## 技术栈与架构

| 层级 | 技术与职责 |
|---|---|
| 前端 | HTML、CSS、原生 JavaScript，展示规划、对话、风险和调整建议 |
| 服务 | Python、FastAPI、Uvicorn，提供 JSON API 并托管前端 |
| Agent | OpenAI SDK，兼容支持 Tool Calling 的服务商，最多执行五轮工具调用 |
| 分析 | Python、Pandas，计算分日行程、补给空窗、候选评分和动态调整 |
| 校验与测试 | Pydantic、Pytest、HTTPX |

```text
用户输入 → FastAPI → Agent → Python 工具
                       ↑          ↓
                       └─ 工具结果 ┘
                           ↓
              解释、结构化行程、工具记录
                           ↓
                 页面展示／用户确认调整
```

配置模型后，大模型负责理解需求、选择工具和解释结果；后端负责校验工具参数、执行计算，并将工具结果回传模型供后续决策。结构化行程取自 Python 工具输出。

未配置模型时使用有限的本地规则演示模式，页面会明确标注，工具仍由 Python 实际执行。

## 安装与启动

建议使用 Python 3.11 或以上版本。以下命令在 PowerShell 中执行：

```powershell
cd D:\Desktop\long-distance-biking
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
python -m uvicorn app:app --reload
```

已有 `.env` 时请保留现有配置，无需再次复制。运行期间保持终端打开，按 `Ctrl+C` 停止服务。

- 应用页面：[http://127.0.0.1:8000](http://127.0.0.1:8000)
- API 文档：[http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)

请通过服务地址使用完整功能；直接打开 HTML 无法调用后端 Agent。

## 大模型配置

在项目根目录 `.env` 中填写：

```env
LLM_API_KEY=你的服务商密钥
LLM_BASE_URL=服务商的OpenAI兼容接口地址
LLM_MODEL=支持工具调用的模型名称
LLM_ENABLED=true
```

`LLM_BASE_URL` 留空时使用 SDK 默认地址。目前代码以 `LLM_API_KEY` 和 `LLM_MODEL` 同时非空作为启用条件；`LLM_ENABLED` 为预留配置，尚不参与模式切换。没有完整配置时仍可运行本地规则演示。

密钥只保存在后端环境变量或已忽略的 `.env` 文件中，不应写入网页或提交仓库。真实模型模式需要服务商支持 OpenAI 兼容的 Chat Completions 和 Tool Calling。

## 使用示例

1. 输入：“我想从成都骑到乐山，三天完成，标准强度，住宿和补给优先。”查看每日行程及工具执行记录。
2. 追问：“哪一天的补给风险最高？需要准备什么？”分析当前行程的补给间隔。
3. 展开途中状态，填写第2天、当天已完成46公里、疲劳高、天气下雨、剩余2小时，点击生成调整建议。
4. 查看调整前后的距离、补给和安全风险，选择确认或取消。取消后保留原计划；可达范围内没有住宿候选时，会提示无法生成可行调整。

天气变化按用户提供的条件处理，不会被描述成实时天气查询结果。

## API

| 接口 | 用途 |
|---|---|
| `GET /api/health` | 检查服务及当前运行模式 |
| `POST /api/agent/plan` | 根据需求生成结构化行程 |
| `POST /api/agent/chat` | 携带历史消息和当前行程进行对话 |
| `POST /api/agent/replan` | 根据途中状态生成待确认调整建议 |

请求字段和校验要求可在运行后的 API 文档中查看。

## 测试

```powershell
python -m pytest tests -q
node --check frontend/agent.js
```

Python 测试覆盖路线里程、评分范围、重规划不修改原计划、接口及异常输入、补给追问和模型工具结果回传。模型调用链路使用替身测试，不能据此认定真实服务商联网调用已经通过验收。

## 数据来源与当前限制

当前支持成都至乐山的 **246km 模拟路线**。路线位置、POI、住宿服务评分、爬升和道路风险均来自项目内置示例数据，并带有模拟来源标识；不代表真实导航距离、商户营业状态、交通监测或实时天气，也不能保证道路安全。

地图为静态示意图，标记不会随 Agent 结果重新定位。自然语言规则演示仅支持有限表达；应用暂不提供服务端持久化会话，行程保存于当前浏览器。

后续可通过数据适配器接入真实地图路线、沿途 POI 和天气服务，保留每项数据的供应商、查询时间和可信度，并完善地图联动、会话存储及浏览器交互测试。
