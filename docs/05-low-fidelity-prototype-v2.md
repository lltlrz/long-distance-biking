# 骑迹计划 V2 低保真模型

## 1. 设计目标与范围

本版本依据《面向长途骑行者的补给感知与分日路线规划工具》更新，保留原模型不变。V2 强化 AI 推荐解释、补给空窗识别和骑行中的动态调整闭环。

## 2. 页面及状态总览

| 编号 | 页面/状态 | 核心任务 |
|---|---|---|
| 01 | 规划输入 | 输入起终点、天数、强度与偏好 |
| 02 | 规划结果 | 从地图和每日卡片判断方案可执行性 |
| 03 | 每日详情 | 理解终点推荐理由与当日风险 |
| 04 | 补给图层 | 判断沿途服务能力与补给空窗 |
| 05 | 动态调整 | 提交疲劳、天气、时间或进度变化 |
| 06 | 影响预览 | 比较调整前后并由用户确认 |
| 07 | 保存/异常状态 | 完成闭环或修正输入后重试 |

## 3. 规划输入

```text
┌──────────────────────┬──────────────────────────────┬──────────────────────┐
│ 规划条件              │ 地图预览                      │ 决策信息              │
│ 成都 → 乐山           │                              │ 尚未生成方案           │
│ 3 天 / 246km          │          路线范围             │ 输入条件后由 AI 拆分    │
│ 强度：轻松 标准 挑战   │                              │ 每日行程并识别补给风险  │
│ 偏好：补给/住宿/安全   │                              │                      │
│ [生成 AI 骑行方案]    │                              │                      │
└──────────────────────┴──────────────────────────────┴──────────────────────┘
```

生成时按钮显示“正在分析路线…”，失败时保留输入并显示“修改条件 / 重新生成”。

## 7. 动态调整抽屉

```text
                              ┌──────────────────────┐
                              │ 调整后续行程          │
                              │ 原因：体力下降        │
                              │ 已完成：46km          │
                              │ 疲劳：较高            │
                              │ [生成调整建议]        │
                              │ [取消]                │
                              └──────────────────────┘
```

入口包括体力下降、天气变化、时间不足和进度滞后。打开抽屉不会修改当前计划。

## 8. 调整影响预览

```text
┌──────────────────────────────────────────────┐
│ 建议：Day 2 提前在丹棱停留                     │
│ 原因：疲劳较高，避免后半程夜骑                  │
├──────────────────────────────────────────────┤
│                   调整前       调整后           │
│ Day 2 终点         夹江         丹棱            │
│ Day 2 里程         88km         76km           │
│ 补给空窗           2 段          1 段            │
│ 综合风险           中            低              │
│ [确认重新规划] [取消]                           │
└──────────────────────────────────────────────┘
```

只有点击“确认重新规划”才应用调整；取消或建议生成失败时，原计划不变。

## 9. 保存与异常状态

- 保存成功：右上角 Toast“当前骑行方案已保存”。
- 起终点无法识别：给出候选地点，不清空输入。
- 天数过少：解释日均里程过高，并建议增加天数或选择挑战强度。
- 无理想住宿点：推荐最近可住宿城镇，并明确里程偏差。
- 路线生成失败：保留规划条件，允许修改后重试。
- 动态数据不可用：显示更新时间或“信息待确认”，不伪装为实时数据。

## 10. 原型交互映射

| 起点 | 操作 | 结果 |
|---|---|---|
| 规划输入 | 生成 AI 骑行方案 | 规划结果 |
| 规划结果 | 点击 Day 2 | 每日详情与地图聚焦 |
| 规划结果 | 切换补给类型 | 地图标记同步变化 |
| 规划结果 | 点击体力下降 | 动态调整抽屉 |
| 动态调整 | 生成调整建议 | 影响预览 |
| 影响预览 | 确认重新规划 | 更新后的规划结果 |
| 影响预览 | 取消 | 未变化的规划结果 |
| 规划结果 | 保存 | 保存成功 Toast |
